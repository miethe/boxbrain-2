# BoxBrain v2 Seed Data Plan

**Purpose:** Create a realistic pilot/demo corpus without requiring production content on day one.

## 1. Seed corpus goals

The seed corpus should exercise these cases:

- one source deck with 8–12 slides;
- one second deck with overlapping/similar slides;
- explicit variants: Executive, Technical, Board, Regional;
- version history: v1.0, v1.1, deprecated v0.9;
- one stale slide;
- one approved canonical slide;
- one restricted/client-sensitive slide;
- two duplicate candidates;
- two similarity-only candidates;
- two ContentBlocks;
- one Storyboard with three sections and gaps.

## 2. Recommended fixture decks

Create synthetic decks around a neutral theme such as “Cloud Modernization Business Case”:

1. Executive Overview Deck
2. Technical Architecture Deep Dive
3. Board Update Pack
4. Regional/EMEA Variant Pack

Avoid real confidential content for the first development corpus.

## 3. Data to seed manually

- Users: viewer, contributor, curator, reviewer, admin.
- Taxonomy: offerings, technologies, sectors, audiences, purposes, stages, regions.
- Approval states and freshness states.
- Notes on at least five content families.
- Persistent comments on at least three objects.
- Review comments on one storyboard slot.
- Review items for duplicate and variant linking.

## 4. Search eval queries

Initial query set:

1. operating margin slide
2. board operating margin slide
3. cloud modernization ROI proof
4. executive cloud transformation narrative
5. technical architecture migration slide
6. stale QBR slide
7. EMEA modernization variant
8. customer proof slide
9. 3 slide ROI story
10. approved executive summary deck

Each query should define expected top families/variants and unacceptable results.

## 5. Demo storyboard

Suggested sections:

1. Why change now
2. Economic case
3. Architecture and migration path
4. Proof and next steps

Add one gap slot in each section to demonstrate recommendations and diagnostics.
